# dimina 高风险评审

## 首轮前

- 列出改动激活的既有机制：OS 任务/页面栈、进程内单例、组件/页面复用、状态生命周期、路由与路径归一化、跨进程消息顺序。
- 对“所有端/入口”建立成员表。端至少考虑 Android、iOS、HarmonyOS、fe；入口按实际 API 枚举，不使用默认清单冒充完整清单。
- 将机制源码和成员表交给 reviewer，不只给 diff 和一个参考端。

## 语义迁移

新建一条产生路径并停用旧路径时（合成事件取代原生事件、新 owner 取代旧 owner、新产物取代旧产物），首轮前先做一次反向枚举，结果并入成员表：

- 全仓搜同一事件/状态/产物的所有派发点，以及所有仍依赖被停用通道的代码，逐个判定是迁移完成、故意保留还是漏网；
- 枚举的定义域是“谁产生、谁消费”，不是改动所在的目录或包。

判据：这类漏网代码通常一行都没改，不在 diff 里。已发生过一次——统一手势合成 tap 并忽略真实指针 click 后，自定义组件宿主仍在 render 层用原生 click 派发 tap，宿主上的 `catchtap` 拦不住祖先 `bindtap`；两侧分属 components 与 render 两个包，按目录取的成员全集把它漏掉了。

## 维度

按风险选 3–5 个：跨端逐成员证据、系统生命周期、复用入口、状态机、时序重入、失败与部分完成、输入归一化、跨边界组合路径、第二次用户交互、相邻功能。导航/栈/生命周期改动强制包含系统生命周期和复用入口；事件、状态或产物改变产生方式的改动强制包含跨边界组合路径。

连续两轮不得重复同一维度。每条结论包含该成员自己的 `file:line` 或运行证据；“其他端同理”只能生成下一项检查。

## 停止

只读评审在计划维度已覆盖、findings 已附证据并报告后停止；未修 finding 作为未决风险返回，不为等待修复重复同一轮评审。包含整改的工作流在已接受 findings 修复并完成一次聚焦复查后停止。两种情况都只报告已覆盖维度下的结果，并列出未验证平台、入口和用户路径。
